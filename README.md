# image_cut

把一个图像拆成 2 个子图，改完之后再严丝合缝地拼回原图。

典型的用法是：把大图切开，把其中一块丢给 AI 修图（inpainting、超分、去水印），
拿回来之后拼回去，且拼回去的结果和原图逐像素一致。

## 运行

```bash
pip install -r requirements.txt
python image_cut.py
```

只需要 Python 3.9+ 和 Pillow（tkinter 是 Python 自带的）。没有其他依赖。

## 拆分

打开图片后，红色分割线就是切割位置。三种调整方式随便挑：

- **拖动**：直接拖红线；在图像上单击可以把它吸过去
- **数字**：`px` 和 `%` 两个输入框双向同步，输入哪个都行
- **微调**：方向键 ±1px，`Shift` + 方向键 ±10px

方向选「垂直」就是左右切，「水平」就是上下切。切换方向时百分比会保留——
59% 在哪个轴都还是 59%。

**放大镜**：鼠标在图上移动时，左下/右下角会显示切割点附近 4 倍放大的像素，
带十字准星和精确坐标。大图缩到画布上时 1px 在屏幕上根本看不出来，靠它才能对准。

点「执行拆分」输出三个文件：

```
照片_p1.png        第 1 块
照片_p2.png        第 2 块
照片_split.json    还原信息
```

> 拆分输出**固定是 PNG**，即使原图是 JPEG。两个原因：JPEG 是有损的，中间过一道
> 就会在接缝处留下可见色差；而且只有 PNG 能把还原信息写进文件内部。AI 修图工具
> 普遍能正常读写 PNG。

## 拼接

选上两个子图就会自动校验并预览。点「执行拼接」输出 `照片_joined.png`。

选第一块之后，另一块会**自动找出来**：先看拆分记录里写了什么文件名，找不到就按
`_p1` / `_p2` 的名字配对。选反了可以点「⇄ 交换」。

### 拼接方向

默认「自动判断」。判断依据会直接写在报告里：

1. **拆分记录**（最可靠）——当初是按哪个方向切的，就按哪个方向拼
2. **图片尺寸**——两张高度相同 → 左右拼；宽度相同 → 上下拼

记录优先于尺寸猜测。因为"两张图宽度碰巧相同"并不意味着它们就该上下拼，
而记录是当初切的时候实打实写下来的。两者不一致时报告里会说明，也可以手动指定。

### 尺寸对不上会拒绝拼接

这是刻意的，不是 bug。举例：

```
子图 2 的尺寸和拆分时对不上：
  期望（拆分记录）：1120×1080
  实际：1120×1078（宽 +0，高 -2）
```

拼接要求两块在垂直于接缝的方向上尺寸完全一致，否则拼出来会错位或缺一块，
"还原成原图"就成了空话。看到这个提示就去把图改回期望尺寸——
AI 修图工具经常悄悄改动尺寸，裁掉多出来的几像素、或补足缺的那几像素即可。

报告可以一键复制，方便直接粘给 AI 问"你为什么把尺寸改了"。

## 还原信息是怎么找到的

因为你会把子图丢给各种工具，它们的输出常常换目录、换文件名、被重新导出，
所以还原信息同时写在三个地方，读取时逐级回退：

| 顺序 | 位置 | 什么时候用得上 |
|---|---|---|
| 1 | PNG 内部的 iTXt 文本块 | 文件被改名、被挪到别的目录都不丢 |
| 2 | 同目录的 `<名字>_split.json` | 图片被别的工具重新导出、内嵌信息被抹掉时 |
| 3 | 同目录里按内容匹配的 `*_split.json` | 改名 + 内嵌信息被抹掉，但 sidecar 还在时 |
| 4 | 按图片尺寸推断 | 完全没有记录时的兜底 |

另外还会做一致性校验：如果两块记录的原图尺寸或拆分参数对不上，会直接报错
「这两个文件不是同一次拆分的结果」——专门挡拿错文件的情况。

**所以：尽量别删 `_split.json`，也别把两块分开放到不同目录。** 当然，就算放了，
通常也能靠 PNG 内嵌信息认出来。

## 一些已经处理好的坑

- **EXIF 方向**：带旋转标记的 JPEG 会自动转正，避免预览躺着、以及被 AI 转正后
  尺寸宽高互换导致莫名其妙的拼接失败
- **颜色模式**：16 位 / CMYK / 调色板图统一转成 8bit RGB/RGBA（AI 工具普遍只吃
  8bit），转换会在界面上明示
- **多帧图**：GIF/TIFF 只取第 1 帧并提示
- **中文路径**：正常支持
- **大图性能**：4000×3000 加载 + 渲染约 0.3 秒；拖动分割线不会重绘图像
- **Windows 文件占用**：打开图片后立刻释放文件句柄，不会挡住你在资源管理器里
  改名

## 文件说明

- `image_cut.py` — 全部代码，单文件
- `requirements.txt` — 依赖（只有 Pillow）
- `test_core.py` — 核心逻辑回归测试（无需图形界面）
- `test_gui.py` — GUI 端到端测试（会短暂弹出程序窗口）

```bash
python test_core.py    # 逐像素往返校验 + 还原信息回退 + 严格校验
python test_gui.py     # 真实驱动界面走完整流程
```

核心测试里最重要的一条是：拆分再拼接之后，结果与原图 `ImageChops.difference`
必须全零。这是这个工具的立身之本，改动代码后跑一下比较放心。
